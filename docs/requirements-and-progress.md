# AskFlow 需求与进展记录

每完成一个可验收的阶段，在这里补记用户需求、实现位置、验证结果和仍需验证的环节。较早的实现按当时状态保留，当前使用方式以对应功能文档为准。

## 开发约定

- 修改前先查已有实现，优先复用成熟库和项目中已验证的解析、校验、渲染函数。
- 新流程替换旧入口时，检查调用方并删除失去用途的界面、接口及辅助代码。合并实际重复的逻辑，端到端验证正常入口。
- 每次提交只包含当前需求相关的代码和文档。记录本次删除或合并的内容、验证结果和仍需验证的环节。

## 2026-11-20 微信聊天整理

### 核心需求

- 以普通聊天作为入口。用一句话指定微信联系人、起止日期或分钟，以及整理目标和输出格式。资料不足时在对话里追问。
- 助手负责按流程查找聊天。文字直接出示给用户，语音优先尝试通过微信转成文字。转写中的英文术语、数字和含糊片段需要保留出处，方便用户校对。
- 在同一对话展示待核对的消息、发送人、时间和语音状态。用户可以直接编辑，核对后发送确认。之后才合并重复意见、按主题分条，导出 Word 或 Markdown。
- 本机 MCP 负责读取微信。整理后的文档保留可以回查的原话和发送时间。原始音频可获取后，再评估项目自己的语音识别模型。

### 实现记录

| 阶段 | 实现与验证 |
| --- | --- |
| 初始微信整理 | 接入社区微信 MCP，按联系人和时间过滤，合并论文意见并导出 Word 或 Markdown。使用模拟聊天和真实 stdio 测试。提交 `c5befdb`。 |
| 语音转写整理 | 纳入已经读到的语音转写，保留缺转写的发送时间、中英术语和待确认项。使用模拟记录测试两种下载。提交 `60844f3`。 |
| 普通聊天入口 | 支持在聊天发送、追问和下载。配置本机社区 MCP，验证后端能发现历史工具。使用模拟数据验证流程。提交 `6254046`。 |
| 聊天内校对与确认 | 普通聊天发起读取，结果展示在同一对话中，可逐条编辑。用户回复「确认整理」后，后端才使用校对后的文字生成报告。删除旧按钮、弹窗和对应的直接导出 HTTP 入口。主聊天与独立文档 MCP 工具共用原有的记录整理和文件生成函数。 |

本阶段通过 72 项后端测试、75 项前端测试和生产构建。用浏览器和合成记录验证了按钮移除、语音校对、刷新恢复、确认门槛及两种格式下载。已通过本机 Python 验证语音扩展能注册成 MCP 工具，并用模拟控件验证其时段范围和重复语音定位。

本机实测发现 Windows 微信恢复窗口后仍只暴露通用外层窗口，社区库无法读取聊天控件。应用会显示这个具体失败原因。需要在桌面微信的无障碍控件可用后继续验收真实转写。

## 相关需求备忘

- Markdown 文档按标题层级切分。优先使用成熟的 Markdown 解析库识别结构，项目保留分块和 overlap 的控制。
- RAG 向量存储后续评估 Milvus 等向量数据库。面试介绍应区分已实现的向量检索和待评估的数据库接入。
- MCP 的项目描述应区分自研文档工具与外部社区微信 Server，按实际接入和验证情况描述。
